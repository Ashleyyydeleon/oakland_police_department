# Dispatcher analysis

Observed data only (no models). Generated by [`dispatcher_story.py`](../../dispatcher_story.py) (`story_*`) and
[`dispatcher_analysis.py`](../../dispatcher_analysis.py) (`dispatch_*`). The same PNGs are in Box at
`02 Oakland Police Dept (OPD)/Outputs/`.

A 911 call waits in two queues, each limited by a different group of staff:

```
Phone rings → answered → incident created → officer dispatched → en route → on scene
|__ Queue 1: call takers __|                |__ Queue 2: available officers __|__ travel __|
```

The CAD log starts at "incident created", so Queue 1 (the phone wait) is invisible in it and needs the phone data.

## Caveats
- The only hourly 911 phone data is Jan 1 – Jun 21, 2024 (public records request 24-6237). 2025–26 answer speed is monthly only.
- Scheduled call takers are the City Auditor's estimate of the 2023 minimum schedule, read off a published chart; actual staffing was usually below minimum.
- r = 0.62 is a moderate association: evening hours have similar calls per call taker but faster answers, so staffing is not the whole story.
- Officer counts are permanent assignments and include officers on leave.

## Data to request
Hourly ECaTS for 2024–26 (calls, answer time, abandoned calls), dispatch-center shift sheets (actual vs minimum staffing by hour),
the dispatcher schedule by position, and the CAD unit-status log. Actual dispatchers on duty by hour would allow a real
staffing-vs-answer-time analysis and hiring impact estimates.
